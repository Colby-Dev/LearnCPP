
   4.1 Introduction to Fundamental Data Types
   ==========================================

   > Bits, bytes, and memory addressing
   ------------------------------------

      	Random Access Memory (RAM) is temporary storage for programs to use, such as when a variable is declared, this is stored on the RAM. The smallest unit of memory is a bit, holding either a 1 or a 0. A byte is a sequence made up of 8 bits. These memory storages on the RAM are organized into memory addresses which allow us to find and access the contents of this memory. 

   > Data types
   ------------

	Since all data on a computer is just a sequence of bits, we use a data type to tell the compiler how to interpret the contents of the memory such as str, int, char, etc. When values are assigned then complied, the compiler encodes them to binary format to allow the RAM and CPU to execute and understand the data. For example, a value of 65 is considered 0100 0001 (4 bytes) and stored in memory at an address assigned to it. 

	Vice versa also happens when we need the program to convert back. The RAM and CPU work together to retrieve the stored content at the memory address and deliver it in a decoded format (from 0100 0001 to 65 in this case) 

   > Fundamental Data Types
   ------------------------

   	The compiler and language itself understand basic types such as doubles and bools. These are called fundamental data types and are something that the lang knows inheritly. 

   > Integer vs Intgral Types
   --------------------------

   	C++ defines these two types differently as show below: 

	* Standard integer type - short, int, long, long long (including their signed and unsigned variants) 

	* Integral types - bool, chartypes and the standard integer types

	All integral types are stored in memory as integer values, but only integers display as its integer value when outputted. Bools will display either 1 or 0 as this is specific to the integral type. Integral types also do not include types that could be integers such as an enum. 

   > Other sets of Types
   ---------------------

   	fundamental data types provide the basic types, whereas compound data types provide more complex data types and allow for user defined data types such as structs or enum magic numbers. 

   > _t suffix
   -----------

	The _t suffix means type which is used in modern c++ to delcare user types instead of built in functions. 


   4.2 - Void
   ==========

   	Void type means no type hence the void meaning. This is an incomplete type which is decalred but not defined, therefore the compiler is aware of the existence but has not allocated memory to the value. Incomplete types cannot be instantiated and have no memory allocation. 

   > Functions that do not return a value
   --------------------------------------

   	Void function types declare that the function does not have a return value. If any is returned an error will raise at compile time. No return statement is needed in these functions. 

   > Deprecated: Functions that do not take parameters
   ---------------------------------------------------

   	Void was used as a way to indicate that a function didnt take a parameter but this is since deprecated as this happens implicitly.

   4.3 - Object sizes and the sizeof operator
   ==========================================

   > Object sizes
   --------------

   	Objects in memory often do not take up jsut 1 byte. Usually they take up multiple bytes at the memory address but when we refer to them in the code we use the variable name, as the compiler takes care of understanding the size and how to retrieve the data from the address. 
	
	The basic understanding of the object size is n bits where n is an integer. The object can hold 2^n unique values, therefore with an 8-bit byte, a byte-sized object can hold 2^8 values. This makes a limit on the amount of values the object can store. Computers have a finite amount of memory and small portions of the memory are used with objects as long as they are in existence. Modern computers have so much memory that its never really an issue except when heavy asset programs are running like games. 


   > Fundamental Data Type Sizes
   -----------------------------

	C++ does not explain many guidelines around memory as it is highly customizable in each program. The basic guidelines are that bytes are 8 bits, integral types are as follow: 

		* char = 8 bits
		* short = 16 bits
		* int = 16 bits
		* long = 32 bits
		* long long = 64 bits

   > The sizeof Operator
   ---------------------

   	The sizeof operator is a built in operator to the standard that will show the size of an object that is instantiated. The operator takes a variable or type and outputs the int of the size type.

   4.4 - Signed Integers
   =====================

	An integer is an integral type that can represent negative numbers and positive numbers (this includes 0). Basically signed integers get their names from the negative (-) infront of the number. Signed integers are native to certain types (short, int, long, and long long). These types can also take the signed keyword to identify them as signed. 

   > Signed Integer Ranges
   -----------------------

   	The size of signed interger ranges match the 2 to the nth power. Therefore an 8-bit signed integer is shown as 2^8 = -128 to 127

   > Overflow
   ----------

   	When a value is assigned to outside a bit range this can lead to undefined behavior. So if a value of 140 is assigned to an 8-bit signed integer the behavior will be undefined and considered overflow. 

   4.5 - Unsigned Integers, and Why to Avoid Them
   ==============================================

   > Unsigned Integers
   -------------------
	
	Unsigned integers can hold only positive numbers (including 0). They are defined using the standard native types with the prefix "unsigned". Unsigned integer ranges from 0 - 255  compared to the range of a signed int of -128 to 127. Both can store 256 values but the ranges are very different. Unsigned integer overflow is similar to signed int in the way that the value is essentially divided amoong the bits and overflow bits get left with the result. For example: 

	unsigned int x = {280};
	cout << x << 

	>>>> 24, (because 280 // 256 would give the remainder of 24. We can think of this as it resetting to 0 after reaching 256)
	
	Because of wrap around and the range of the unsigned and signed ints there are certain situations when one is better than the other. In most cases signed ints are better as overflowing bottom values is a common  struggle with unsigned ints. Wrapping with signed ints is also a common issue as the value ranges are not as large. 

	
   4.6 - Fixed width integers and size_t
   =====================================

	The int data type is not fixed because we need to have optimization for the architecture we are building on. This is something that allows us to build software specific to machines that it will be ran on. Because of this we can have issues with integers wrapping and creating bugs and undefined behaviors. C++ addresses this by used Fixed-width integers. 

	> Fixed-Width Integers
	----------------------

	Fixed width ints are ways to guarantee that ints be the same size on any architecture. They are used from the cstdint header file. Regardless of the computer architecture 32 or 64 this int will behave the same if wrapping is to occurr or if it holds a large number. 

	(see Example 2)

	> Other Fixed-Width Downsides
	-----------------------------

	Fixed width ints do have some drawbacks. They are not always guarenteed to be defined and only exist on where there are fundamental integral types, thus the program will not compile if it does not recognize this. Fixed width ints can be slower as well. In some cases compiling the larger bit may be better. 

	> Fast and Least Integral Types
	-------------------------------

	To help address the above downsides, C++ uses std::int_fast#_t and std::uint_fast#_t to provide the fastest signed/unsigned integer type with a width of at least # bits, where # = 8,16,32. This helps the CPU process the type as quickly as possible. 

	We also have the std::int_least#_t and uint version to provide the smallest signed and unsigned integer. These both come from <cstdint> header file. 

	(see Example 3)

   4.9 - Boolean Values
   ====================

	Boolean types exist as yes/no options in the form of True and False. They are declared with the bool keyword followed by the variable name and the assignment of the true or false keyword. Even though these assignments are labeled as "True" or "False" they are actually stored in memory as 0 or 1. Shown here: 

	int main()
	{
		std::cout << true << '\n'; // prints bools as 0 or 1
		std::cout << !true << '\n';

	}

	std::boolalpha will allow these to print actual words true or false

   > Integer to Boolean conversion
   -------------------------------

   	Integers can be converted to bools without issue as long as the value corresponds to a valid boolean state of true (1) and false (0). Bools default to false therefore allowing user input on a boolean is not recommended because they because false.

   4.12 - Type Conversion and Static_Cast
   ======================================

   	The process of converting data from one type to another type is called type conversion. Thus, an int argument can be converted to a double by adding the decimal point. This conversion is known as an implicit type conversion and the compiler can do this conversion as the program executes. 

   > Type Conversion of a Value Produces a New Value
   -------------------------------------------------

   	A new result is given when the conversion takes place. The type conversion of a value to another type of value behaves much like a call to a function, which the return type matches the target of the conversion. 

   > Explicit Type Conversion via Static_cast
   ------------------------------------------

   	Explicit type conversion allow us to explicitly tell the compiler to conver a alue from one type to another type. To preform an exolicit type conversion we can use the static_cast operator. The syntax looks like: 

		static_vast<new_type>(expression) 

	Static_cast takes the value from an expression as input, and returns that value converted into the type specified by new_type. 

   > Sign Conversions Using static_cast
   ------------------------------------

   	Signed integral values can be converted to unsigned integrals and vice versa. In this case as long as the value is still in a usable range regardless of the value remains unchanged.
