

	Chapter 5: Constants and Strings 
	================================


   5.1 Constants and Strings
   -------------------------

   	A constant is a value that may not be changed after initialization and during the program's execution. C++ supports two kinds of constants: 

	* Named constants are constant values that are associated with an identifier. These are 
	  also sometimes called symbolic constants. 

	* Literal constants are constant values that are not associated with an identifier. 

   Types of Named Constants
   ------------------------

   	There are three ways to define a named constant in C++: 

		* Constant variables
		* Object-like macros with substitution text
		* Enumerated constants 

   Constant Variables
   ------------------

   	There could be cases where constants are needed so that data is unchanging from the programs execution. We can do this by declaring a variable with the const prefix: 

		const double gravity = { 9.8 } 
		int const sidesInSquare = { 4 }

   Const variables must be initialized
   -----------------------------------

   	Const variables must be initialized when you define them, then the value cannot be changed via assignment. For example: 

	int main(){

		const double gravity = { 9.8 } 
		const int gravity2 = {9.8}

		gravity2 = 9.9 // This produces an error

		} 
   
   Naming your const variables
   ---------------------------

   	There are a number of different nameing conventions that are used for const variables. Most people use the 'k' prefix to indicate that the variable is a const so you can avoid trying to assign it to another value. 

   Const Function Parameters
   -------------------------

   	Function parameters can be made contants with the const keyword. In modern C++, we do not make value parameters const because we generally do not care if the function changes the parameter, since its just the copy that will be destroyed at the end of the function. 

   Const return values
   -------------------

   	Dont use const when returning values. These values are ignored because the value is technically const already and is destroyed regardless at the end of the function. 

   Why variables should be made constant
   -------------------------------------

   	If a variable can be made a constant, it generally should be made constant. This is important for a number of reasons: 

	* It reduces the chance of bugs. By making a variable constant, we know it is impossible to change at runtime. 
	* It provides more opprotunity for the compiler to optimize programs. 
	* It reduces the overall complexity of our programs and makes them easier to understand. 

   Object-like macros with substitution text
   -----------------------------------------

   	In chapter 2, we looked at the preprocessor macros defining variables (like in the example below) this is a constant value and allows us to define this variable that will not change: 

		#include <iostream> 

		#define MY_NAME "Colby" 

		int main(){

			std::cout << "My name is: " << MY_NAME << std::endl;

			return 0; 

		}

	
   Prefer constant variables to preprocessor macros
   ------------------------------------------------

   	We prefer variables to preprocessor macros because, while macros are great they do not adhere to the scoping logic of C++ and can create issues. One example of this is defining a macro then trying to use that as a constant in a function call. This normally wouldnt be an issue but it presents a conflict where you have a constant macro then a constant parameter which could not be the same value and throw an error.
